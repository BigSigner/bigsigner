# Sign a transaction

Create the transaction in a coordinator such as Sparrow. Export it as a PSBT and move that PSBT to BigSigner without using the network. A QR code or a file you carry yourself is the intended path. The coordinator is not trusted. BigSigner checks the PSBT against the wallet you have selected.

PSBT version 0 and version 2 are read. A version 0 PSBT that contains a per-input required locktime is rejected. Bitcoin transaction versions 2 and 3 are accepted. Other versions are rejected.

## What has to match

Every input must belong to the selected wallet. Each input needs a derivation path. If its paths are supported but its fingerprints or wallet type do not match the selected wallet, the error identifies the other loaded wallet when possible. If that wallet is not loaded, it says This transaction does not belong to this wallet. This also covers MultiSig wallets whose participant sets only partly match. If a supported path is otherwise valid but uses the other network’s coin type, the error names the currently selected network and the network indicated by that path. A mainnet path uses `0h`; testnet and regtest share `1h`, so that path is described as belonging to testnet or regtest. For a multisig input, every cosigner must use the same receive-or-change step and the same address index. One key ending in `/0/5` and another in `/1/5`, or `/0/6`, is rejected.

All inputs in the transaction must use the same combination of accounts. If that combination is not the one currently selected, the error asks you to go back to the wallet and change the account indexes. Inputs that disagree with each other about the accounts are rejected. The order in which a coordinator lists MultiSig participants does not affect this comparison.

Fingerprints and derivation paths are claims made by the coordinator. BigSigner derives each input's keys from its loaded seed or account key expressions and compares every participant's public key with the PSBT. Taproot uses x-only public keys. BigSigner also compares the spent output's locking script with the script derived from the selected wallet, checks a supplied MultiSig witness script, and rejects script-tree metadata for its Taproot key-path wallets. A missing MultiSig witness script is derived before signing.

Every PSBT input must supply the spent output's amount and locking script in a witness UTXO. The full previous transaction is optional and cannot replace that witness UTXO. If included, BigSigner checks its transaction id and referenced output, and requires its amount and script to match the witness UTXO. Validation and signing use the witness UTXO. These checks use only data carried in the PSBT; the device does not look up transactions online.

An output is change only when its wallet policy, fingerprints, and complete account combination match the spending wallet. Its keys must share one branch and address index. Either Receive or Change addresses can qualify. BigSigner derives the descriptor from its loaded seeds or key expressions, checks every supplied participant public key, and compares the derived locking script with the actual output script. Supplied witness scripts and Taproot metadata are checked too. A complete ownership claim with a different public key or address rejects the PSBT. Missing participants cannot establish change. A proven address in another account or wallet stays under Outputs with its wallet and address information. MultiSig wallets with different thresholds are different wallets even when their fingerprints match.

When an output claims the spending wallet but its derived address does not match, the error says:

> An output claims to belong to this wallet, but its address does not match the supplied derivation path. This may be an attempt to spoof a change output.

When the output claims a different account from the spending account, insert (on a different account) after this wallet. For MultiSig, compare the full fingerprint-to-account mapping; a difference for any participant adds the note. Use the captured spending accounts throughout validation and review.

The signature hash must be SIGHASH_ALL. Taproot also allows the default sighash. SIGHASH_NONE, SIGHASH_SINGLE, and ANYONECANPAY are rejected. A PSBT that contains PSBT_GLOBAL_TX_MODIFIABLE is rejected on version 0 and version 2. A signature already on an input is checked against the transaction. Every signature on a multisig input is checked. A signature that does not match is rejected.

## Loading progress

After the file is read, or the last QR part is assembled, BigSigner shows a progress screen with no title. The text names the check in progress, such as Parsing input 7 of 80, and a bar below fills from empty to full. Touches do nothing until Transaction Signing opens, or until Error loading PSBT replaces it.

## Transaction Signing

A PSBT that passes the checks opens Transaction Signing. The header says Spending from Wallet:, then the wallet name and Account: 0 (default) or Account: 3 (non-default). A multisig account line lists every key's index, such as Account: 0, 0, 0 (default). The parenthetical is default only when every index is 0. Under the account line, Transaction Id is a chevron, closed at first. Opening it shows the transaction id as four centered monospace rows, the same way an input shows a previous transaction id. A wallet name does not start a line with a word of two letters or fewer. A block-height locktime adds a grey note that the transaction can be mined only after that block height. The exact height is not included: Bitcoin accepts the transaction in the next block. More Information, closed at first, explains why wallets set a locktime near the chain tip.

Warnings are centered. There is one OP_RETURN warning: red when any OP_RETURN carries bitcoin, otherwise yellow when an OP_RETURN is present. A fee of 100000 sats or more is a red warning and the fee section is red. A timestamp locktime, a relative locktime, and a Replace-by-Fee disabled input are yellow warnings. The relative-locktime warning says to see below for more details.

Amounts are satoshi counts shown as BTC strings. The count is padded to at least nine digits and the point is placed eight digits from the right. It is not divided by a float. An OP_RETURN of zero sats is shown on the label line as Amount (BTC): 0. Any other zero amount uses that same line. The largest amount, 21,000,000.00000000, fits on one line.

The output heading says 1 Output or the number of outputs. Those cards skip money that returns to the spending wallet and the same account combination. When every output returns to that wallet and account combination, the heading is replaced by a note that the transaction sends all funds back to the same wallet, except for the fee. Other outputs show the address in groups of four. A derivation that matches a loaded wallet shows that wallet, its account combination, and Receive or Change Address with the address index. Otherwise the card says External Address and offers Search for Address in Loaded Wallets.

Search for Address in Loaded Wallets opens Address Search. Choose an inclusive From Account Index and To Account Index range, and a Starting Address Index. The account range starts two below the spending wallet's lowest selected account, with a minimum of zero, and ends five above that start, capped at 2147483647. The starting address index defaults to zero. Loaded seeds supply every account in the range; external keys supply only their loaded accounts. The search checks Receive and Change in matching wallet types and every available combination of MultiSig participant accounts. If the account range is too large, narrow it. If a single account still exceeds the search limit, reduce the loaded wallets.

Start Search turns into a red Stop Search button and the selectors are disabled. The centered Searching Address Index: label shows the address index below it. Stop Search keeps the settings and shows Last Searched Address Index: with the last index checked; stopping during preparation leaves that text empty. Changing either account-range value or starting another search clears it. Back stops the search and returns to Transaction Signing.

A match opens a success popup on Address Search. Pending touches are discarded, and a fixed 250 ms gap begins after the popup is displayed. Ignored touches do not extend the gap. For a match in the same wallet and account combination this transaction spends, the notice says Address found in Receive addresses: #120 or Address found in Change addresses: #120, using the index that was found. Another account of this wallet says Address found in account # and the account number, or for a multisig wallet Address found in account-sequence and the account indexes. Another wallet says Address was found in wallet and that wallet's name. The name and the account sequence break after a comma.

OK reloads Transaction Signing through the progress screen, repeating every input, output, and signature check. Discovered public keys, fingerprints, and full paths are kept as additional output information; the PSBT's output origins are not rewritten. This information is checked against the actual output script and derived again from loaded keys. It fills missing participant origins without overriding any claim supplied by the PSBT, including when a MultiSig output initially names only some participants. Further searches retain earlier discoveries, while opening a new PSBT starts with none. Dismissing the popup without OK leaves the discovery unapplied. After validation, a recognized address in another account or wallet stays under Outputs with its address information and no search button. Only proven addresses in the spending wallet and its selected account combination move to Change Outputs.

Change sits above the inputs. Its heading is 0 Change Outputs with no chevron, or 1 Change Output, or the number of change outputs. The list starts closed. It starts open when a change output is a receive address and that is warned, or when there is more than one change output. The input heading says 1 Input or the number of inputs. A change card shows the address and Change Address or Receive Address with the index. A receive address there is yellow when the transaction also pays somewhere else. More than one change output is a yellow warning, because that is unusual although a wallet may do it for privacy. A change output on a receive address is a yellow warning too when the transaction also has an output that does not return to this wallet and account: it is unusual, but mostly harmless. A consolidation that sends every output back to the same wallet and account does not warn, and the receive address is not yellow. Using a receive address for that consolidation is usual.

The fee is every input minus every output, including change and OP_RETURN. The fee rate is that fee divided by the virtual size, shown with two decimal places. The locktime section says the transaction could be mined right away when there is no absolute locktime and no relative locktime. Otherwise it names a block height, shows a UTC timestamp, or says there is no absolute locktime while a relative one remains. Inputs start closed unless a sequence is not 0xFFFFFFFD. An open input shows the previous transaction id, the output index, the amount, the sequence in hex, and Show Input QR. That code can be the raw txid and output index, or a link to that output on mempool.space or blockstream.info. On testnet or regtest, those two links have a control above Brightness that chooses Testnet, Testnet4, or Signet. Those are the networks both sites publish. Raw has no such control. A sequence of 0xFFFFFFFE says Replace-by-Fee is disabled and that the network no longer honors that flag. A lower sequence is a relative locktime in blocks, or in units of 512 seconds. A time duration breaks onto another line only after a comma.

Sign Transaction signs the one loaded seed. A multisig wallet prints a grey note above the sign buttons. It names the fewest signatures already on every input, and how many more that wallet's threshold still needs. If any input has none, the note says so and names the full threshold. More than one loaded seed shows one button per seed, named Sign Transaction with and then the first two words and the last two words of that fingerprint name. A seed that has already signed every input has its button disabled, with a grey note, Already signed by key, and the fingerprint name. Continue under those buttons stays disabled until one of them is used. While a signature is computed, the button that was tapped reads Signing… and is grey, other sign buttons stay disabled, and taps do nothing until it finishes. When signing ends, pending touch events are flushed from the device and a short gap starts after that frame is painted, the same way Searching addresses ignores a press that landed during the wait. Signing one seed stays on this screen and updates the note. Back from the signed result shows the PSBT that was loaded. Show QR Code opens Signed Transaction and offers Animated UR, Static UR, Base64, Specter Animated, and BBQr. Back to Wallet near the bottom clears the back stack and opens the spending wallet. Static UR is one code. Animated UR, Specter Animated, and BBQr cycle about twice a second when they have more than one code. Brightness on that screen, and on an input's QR, dims or brightens the whole screen so the panel does not blind the camera. Black stays black. Export to File writes a binary PSBT as transaction-signed.psbt, or base64 text as transaction-signed-base64.psbt.

Any number of OP_RETURN outputs is accepted, including one that carries bitcoin. That matches Bitcoin Core 31's default relay policy. Each script must be OP_RETURN followed only by data pushes, and the scripts together must be at most 100000 bytes. Any other output must be P2PKH, P2SH, P2WPKH, P2WSH, or P2TR. A P2WSH output is a 32-byte witness program. The script inside it is not visible, so it is not called a multisig. A legacy P2PKH output below 546 sats is refused, and a P2SH output below 540 sats is refused. A Native-Segwit SingleSig output below 294 sats is refused, and a P2TR or P2WSH output below 330 sats is refused. A legacy address starts with 1. A wrapped-Segwit address starts with 3. Inputs stay limited to Native-Segwit SingleSig, Native-Segwit MultiSig, and Taproot SingleSig, because malleability is a problem for legacy inputs. A seed that has already signed every input does not get another signature from that seed. A transaction over 400000 weight units, which is 100000 vB, is refused. That is Bitcoin Core's maximum standard weight. A transaction with more than 100 inputs, or more than 100 outputs, is refused so Transaction Signing can keep a short window of pre-rendered scroll tiles in RAM.

## Signing

BigSigner adds a signature only for a fingerprint whose seed is loaded. Watch-only keys are shown as unable to sign. After a signature is added, return the PSBT to the coordinator by QR or by a file you explicitly export. Do not leave a seed on a device that still has a network connection.
